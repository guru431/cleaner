# Проверка backlog 15.11.2026

Разобраны 25 замечаний FINDINGS.md от 14.11; IDEAS.md не содержал предложений.
Восемь ложных или отклонённых замечаний перенесены в FINDINGS-archive.md с причинами.

Исправлены:

- Формы администратора получают минимум пароля из auth.MIN_PASSWORD.
- Проверка nftables требует TCP reset перед заключительным reject, как генератор
  cleaner-egress.sh. Семантика сверена с [руководством Netfilter](https://www.netfilter.org/projects/nftables/manpage.html).
- Кодек проверяет форму правил и Base64; повреждение даёт безопасное сообщение без содержимого чата.
- OCR retry не допускает нулевую паузу.
- Маскирование ключа при чтении ошибки провайдера учитывает секрет, пересекающий границу
  вывода. Запас чтения не попадает в вывод после сокращения текста маскированием.
- SSE ждёт queued/running и заново ищет live; done выдаётся для терминального состояния.
- agent_capture проверяет JSON и list[list[dict]] до запуска HTTP и создания каталога записи.
- Убрана повторная проверка api_writable_chat из двух маршрутов с проверяющей зависимостью.
- Для Windows явно записано требование закрытых NTFS ACL до записи ключей и базы;
  CLI не обещает там защиту POSIX 0600. Автоматическая смена ACL не добавлялась.
- PDF остаётся открытым на весь разбор и OCR; страницы и bitmap рендера закрываются.
- Повреждённая запись журнала заменяется видимой заглушкой, остальные записи доступны.
- Восстановитель ответов строится лениво: просмотр одного входного текста его не создаёт.
- CheckpointBusy не создаёт событие agent_pruned с отрицательным числом чатов.
- Отказ слишком длинному текстовому файлу не выделяет строку длиной max_text_chars + 1.
- Один обработчик paste выбирает одно поле, при неоднозначном назначении вставка не перехватывается.
- EventSource закрывается при окончательной ошибке либо трёх неудачных подключениях подряд;
  сообщение об обрыве не стирает показанную часть ответа.
- Поиск замен пропускает строки, где нет третьей ячейки.

Шаблон заполнения замера памяти не сохраняется в объектах рабочих чатов: commit_chat
сериализует его отдельно для каждого чата. Это пояснено в скрипте.
