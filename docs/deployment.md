# Установка Cleaner на Linux

Рабочий профиль хоста содержит частные адреса и сети и хранится вне Git.
Скопируйте `deploy/hosts/example.conf` в `deploy/hosts/<hostname -s>.conf` и задайте:

- `HOST_IP` — адрес интерфейса службы, `CERT_NAME` — имя в сертификате.
- `CLIENTS` — разрешённые сети клиентов через пробел; каждая должна входить в `INTERNAL`.
- `INTERNAL` — сети, в которые службе разрешено обращаться, включая `127.0.0.0/8`.
- `GATEWAY` — локальный шлюз в формате `узел:порт`.
- `SERVER_GUARD` — `1`, если установлен серверный `ai-egress-guard.sh`, иначе `0`.
- `GATEWAY_KEY_HINT` — инструкция выпуска ключа без самого значения ключа.

Пример из Git ограничен петлёй и не открывает службу другим компьютерам. Профиль — shell-файл,
который выполняется от root, поэтому его владелец и каталог доставки должны быть защищены от записи посторонними.

## Доставка и установка

Нужны Python 3.12, systemd, nftables, ufw, openssl и серверный механизм `ufw-failsafe`.
Для нового сервера сначала подготовьте и проверьте страховку отката экрана.
Перед обновлением дождитесь завершения активных заданий: установщик останавливает службу при замене кода.

1. Распакуйте `git archive HEAD` в принадлежащий root каталог с правами 0700.
2. Отдельно добавьте туда рабочий `deploy/hosts/<hostname -s>.conf`: Git его не включает.
3. Запустите `sudo bash <каталог доставки>/deploy/install-cleaner.sh <каталог доставки> <первый администратор>`.
   Логин требуется при первой установке; пароль вводится интерактивно и не передаётся аргументом.
4. Передайте `CLEANER_GATEWAY_KEY` через `/etc/cleaner/cleaner.env` без вывода значения.
   Адрес шлюза, модель и OCR задайте на странице настроек локальной модели.
5. При необходимости загрузите модели от учётной записи службы и выполните
   `sudo bash /usr/local/sbin/check-cleaner.sh`.
6. Проверьте новое SSH-подключение и доступ из разрешённой сети, затем остановите таймер `ufw-failsafe`.

Другое имя профиля выбирается переменной `CLEANER_HOST`. Установщик сохраняет его в `/etc/cleaner/host.env`.
Настройки и ключи — `/etc/cleaner/`, база и данные — `/var/lib/cleaner/`, код — `/opt/cleaner/`.
Повторная установка сохраняет существующие настройки, сертификат, главный ключ и базу;
при ошибке обновления установщик восстанавливает прежние код, окружение, юнит и копию базы.

## Проверки локального периметра

`tests/test_deploy.py` проверяет все локальные профили, их полноту и включение `CLIENTS` в `INTERNAL`.
Для сверки с внешним экраном задайте `CLEANER_SERVER_GUARD` (путь к его скрипту) и
`CLEANER_HOST_PROFILE` (путь к рабочему профилю). Для периметра с полями `CLEANER_PORT` и
`CLEANER_NETS` задайте также `CLEANER_PERIMETER_CONFIG`. Без этих переменных внешние сверки пропускаются.

Сетевые ограничения для порта 5464 в другом проекте или на маршрутизаторе обновляются вместе с профилем.
Скачанные модели и SQLite остаются вне Git; базу размещайте на локальном диске.
