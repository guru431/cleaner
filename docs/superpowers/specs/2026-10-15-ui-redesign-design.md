# Cleaner — новый вид веб-интерфейса

Дата: 15.10.2026. Дополняет раздел 14 [спецификации](2026-10-13-cleaner-design.md); номера `SEC-…`, `NFR-…`, `FR-…` отсылают к [ТЗ](../../../TZ.md).

## 1. Цель и рамки

Интерфейс собран как заготовка: голые формы столбиком, стили на 33 строки. Нужен вид рабочего инструмента — плотный, единый на всех 17 страницах, со светлой и тёмной темой.

**Меняется:** шаблоны `cleaner/web/templates/*.html` (вид и расстановка), `static/app.css` (пишется заново), `static/app.js` (дополняется), новые `static/theme.js` и `static/icons.svg`.

**Не меняется:** маршруты, методы, имена полей форм, CSRF, заголовки безопасности и CSP, обработчики и данные, которые они передают в шаблоны. Подписи, на которые опираются пользователи и тесты, по возможности остаются дословно.

**Вне рамок:** мобильная версия (ТЗ, раздел 3), обновление страниц без перезагрузки, перетаскивание файлов, всплывающие окна, новые данные на страницах (например, число элементов в списке чатов).

**Дополнение 21.10.2026 (аудит интерфейса, поручение владельца).** Поведение на JS шире решения 15.10 «только вкладки, тема, прокрутка»: перезагрузка по опросу и по концу потока не сбрасывает начатый ввод, копирование сообщает об отказе буфера, тема — три режима с возвратом к системной (раздел 6). Сводка проверки не утверждает больше, чем знает проверка утечек; подсказка у вопроса локальной модели называет, куда уходят оригиналы (раздел 5). Обновление страниц без перезагрузки по-прежнему вне рамок: готовый результат показывается перезагрузкой, только позже — по кнопке.

**Ограничения:**
- SEC-9: ничего с внешних адресов; CSP `default-src 'self'` запрещает встроенные стили (`style=`, `<style>`), встроенные скрипты и обработчики `on…=`. Всё — файлами в `static/`.
- NFR-7: русский язык, актуальные Chrome, Edge, Firefox, ширина экрана от 1280 точек.

## 2. Решения владельца (15.10.2026)

| Вопрос | Решение |
|---|---|
| Охват | Стиль и расстановка; поведение на JS — только вкладки, тема, прокрутка |
| Визуальное направление | «Плотный рабочий инструмент»: тёмная верхняя полоса, мелкий шрифт, рамки вместо теней, моноширинный текст элементов, действия в заголовке элемента |
| Тёмная тема | Есть; по умолчанию — как в системе, плюс переключатель в шапке, выбор запоминается в браузере |
| Экран проверки | Панели «Оригинал / Очищенный» на всю ширину, остальное во вкладках |
| Реализация | Свой CSS на переменных, системные шрифты, иконки одним SVG-файлом; без фреймворков и сборки |

### Шрифты и размеры

- Интерфейс: `"Segoe UI", system-ui, sans-serif`, 13 px, межстрочный 1.45.
- Тексты элементов, панели проверки, замены, выражения шаблонов: `Consolas, "Cascadia Mono", monospace`, 12,5 px.
- Заголовок страницы — 16 px полужирный; заголовок раздела — 14 px.
- Скругление 6 px, рамка 1 px `--line`, без теней. Отступы — шаг 4 px.

### Элементы

| Элемент | Вид |
|---|---|
| Кнопка | Рамка `--line`, фон `--bg-sub`. Основная (`.primary`) — фон `--primary`, белый текст. Опасная (`.danger`) — текст `--bad`. Высота как у поля. Недоступная (`:disabled`) — у любой, и основной, и опасной: фон `--bg-sub`, рамка `--line`, текст `--muted`, без подсветки при наведении; почему недоступна — в `title`. Итог действия на самой кнопке (копирование) — словом в подписи и цветом в придачу: `data-state="done"` — `--good`, `failed` — `--bad` |
| Фокус с клавиатуры | `:focus-visible` у кнопок, ссылок, `summary`, вкладок и выделений (`mark`) — сплошная обводка 2 px `--accent` с отступом 1 px; на верхней полосе — `--top-fg`. Кольцо с прозрачностью терялось на тёмной полосе и на подсветке |
| Состояния | Идёт — серым словом с многоточием («Обрабатывается…», «идёт проверка»); готово — `good`, ошибка — `bad`, недоступно — `:disabled`. Значок несёт слово, а иконка (`check`, `warning`) — в придачу: цвет один ничего не сообщает |
| Поле, список, многострочное поле | Рамка `--line`, фон `--bg`; при фокусе рамка `--accent` и кольцо 3 px из `--accent` с прозрачностью. Кнопка выбора файла оформлена как обычная кнопка (`::file-selector-button`) |
| Значок (`.badge`) | Скруглённая плашка; варианты `good`, `warn`, `bad` — цвет и фон из переменных |
| Сообщение (`.flash`) | Строка на всю ширину с фоном `--warn-bg` / `--bad-bg` / `--good-bg`; заменяет нынешние `p.warn`, `p.error` |
| Панель (`.panel`) | Рамка; заголовок (`.panel-head`) на `--bg-sub`: название полужирным, состояние серым, действия справа; тело (`.panel-body`) |
| Таблица | В панели; заголовки на `--bg-sub`, строки через `--line-soft`. Длинное неразрывное значение (ключ, base64) переносится в любом месте — только в колонках значений; тип и число не переносятся (`td.nowrap`, `td.num`), список замен — только между словами (`td.words`): иначе рядом с длинным ключом они ломались посреди слова. Колонка действий (`td.actions`) — по своему содержимому, у правого края: свободная ширина достаётся колонкам данных, а не кнопкам |
| Вкладки (`[data-tabs]`) | Ряд кнопок над рамкой; выбранная сливается с телом |
| Переключатель (`.toggle`) | Кнопка-«таблетка» с бегунком; `aria-pressed` отражает состояние |
| Раскрывающееся (`details.menu`, `details.inline`) | Меню ⋯ и формы «Изменить» / «Переименовать» — на `<details>`, без JS |
| Иконка | `<svg class="icon"><use href="/static/icons.svg#имя"></use></svg>`, 14 px, цвет `currentColor` |

Иконки в `icons.svg` (символы `<symbol id="…">`, контурные, 16×16): `search`, `plus`, `copy`, `download`, `edit`, `more`, `sun`, `moon`, `auto` (круг, залитый наполовину, — тема как в системе), `warning`, `check`, `x`, `file`. Значки из шрифта (эмодзи) не используются: в Windows они цветные и разные в разных браузерах.

## 4. Каркас страниц

**Шапка** (`base.html`, для вошедшего): верхняя полоса `--top`: «Cleaner», пункты «Чаты» и «Настройки» (администратору), текущий раздел выделен фоном `--top-on`; справа логин, кнопка темы и «Выйти». Кнопка темы (макрос `theme_toggle` в `_ui.html`) показывает действующий режим иконкой и словом — «как в системе» (`auto`), «светлая» (`sun`), «тёмная» (`moon`); какой из трёх виден, выбирает CSS по `data-theme` на `<html>`, без JS. Перед словом — скрытое «Тема:» для читалок: видимое слово и есть имя кнопки, скрытые режимы в него не входят. Текущий раздел определяется по `request.url.path`: `/settings…` — «Настройки», остальное — «Чаты».

**Подключение файлов в `<head>`:** значок вкладки `favicon.svg` (`<link rel="icon">`: без него браузер сам запрашивает `/favicon.ico`, которого нет, и пишет в консоль 404); `app.css`; `theme.js` без `defer` — до отрисовки; `app.js` с `defer`.

**Вход** (`login.html`): фон `--bg-sub`, по центру «Cleaner» с подписью «Очистка текста перед облачной моделью», под ней карточка-панель шириной 300 px: ошибка сообщением `bad`, поля «Логин» и «Пароль» с подписью над полем, основная кнопка «Войти» во всю ширину. Под карточкой по центру — та же кнопка темы, что в шапке.

**Ошибка** (`error.html`): панель с заголовком «Ошибка {код}», текстом и ссылкой «К списку чатов».

## 5. Экраны

### Чаты (`chats.html`, `chat.html`, `_sidebar.html`)

Сетка ниже шапки: колонка списка чатов 230 px и рабочая область. Обе — на высоту окна; список прокручивается сам, рабочая область — сама.

**Список чатов:** вверху форма создания (поле «Название (необязательно)» и основная кнопка «Новый») и поле поиска с иконкой. Ниже пункты: название и время изменения серым; текущий — белый фон и полоса `--accent` слева. «Чатов нет» — серым.

**Пустое состояние** (`chats.html`): по центру рабочей области серым — нынешний текст «Выберите чат слева или создайте новый…».

**Шапка чата:** название (16 px; длинное обрезается многоточием, целиком — в подсказке `title`, как и в списке чатов и в «хлебных крошках»), рядом `details.inline` с иконкой `edit` — форма переименования на месте, под шапкой от её левого края (от карандаша, который длинное название уводит вправо, форма выходила бы за рабочую область); переключатели слоёв 4 и 5 — каждый своей формой `POST /chats/{id}/layers`, на кнопке «Слой 4» / «Слой 5», полное название и состояние — в `title` («Слой 4 — модели распознавания имён: включён»), состояние — `aria-pressed`; справа ссылка «Таблица замен» (в одну строку) и `details.menu` (⋯) с формой удаления чата (прежняя галочка подтверждения и кнопка `danger`).

**Лента:** элементы — панели друг под другом.
- Заголовок входного элемента: «Текст N» / «Файл N» / «Инструкция для модели N», серым состояние; справа «Проверка», «Скопировать», «Скачать .txt» (последние две — только у выдаваемого).
- В очереди или в работе: в заголовке серым «В очереди… / Обрабатывается…» и ход (`data-poll`, `data-progress` как сейчас), тела нет.
- Ошибка: сообщение `bad` в теле и кнопка «Повторить».
- Выдача заблокирована и «прежний вариант содержал открытым» — сообщения `bad` и `warn` в теле над текстом.
- Ответ: заголовок «Ответ {провайдер} — {модель} N» / «Ответ локальной модели N»; справа «Скопировать». Ответ облака по мере получения (`data-stream`) — серым в теле, «Остановить» в заголовке. «Ответ неполный» — сообщение `warn`. Счётчики — мелкой серой строкой под текстом, прежние слова. «Как получено» — `<details>` под счётчиками.
- При открытии чата лента прокручена к последнему элементу, по ссылке с `#item-…` (после ответа, отправки, вопроса локальной модели) — к этому элементу. После перезагрузки по опросу или по концу потока она там же, где её читали, если читали не самый конец (раздел 6).

**Низ рабочей области** закреплён (`position: sticky`), фон `--bg-sub`:
1. Строка отправки: «Облачная модель» со списком и кнопкой «Выбрать», основная кнопка-ссылка «Отправить очищенный чат…» (если подключение выбрано), справа «Спросить локальную модель» (если доступна). Без подключений — серым прежняя фраза о ручном режиме. Подсказка (`title`) у «Спросить локальную модель» называет, куда уходят оригиналы, по адресу локальной модели из настроек: петлевой — «Без очистки: оригиналы остаются на этом сервере (локальная модель по адресу 127.0.0.1:30000)», иначе — «Без очистки: оригиналы уходят локальной модели на узел {узел:порт}». Частный или доверенный адрес (FR-9.1) — уже другой сервер, и прежнее «текст не покидает сервер» было неправдой (аудит 21.10.2026). В подсказке только узел и порт, без учётных данных из адреса и без ключа.
2. Вкладки «Текст / Файл / Инструкция / Ответ вручную» — прежние четыре формы без изменений полей. Поле и основная кнопка в одну строку, кнопка справа снизу. Подписи-пояснения (допустимые форматы файла, «очищается так же и уходит в системную часть запроса») — серым под полем. При открытии чата выбрана «Текст»; выбранная запоминается для этого чата (`data-tabs-remember`), как вкладки проверки: перезагрузка по концу задания возвращала редактор на «Текст», даже если писали ответ вручную.

### Проверка (`review.html`)

Сверху вниз:
1. Строка «хлебных крошек»: «{название чата} / Проверка текста N»; справа «Таблица замен» и кнопка «Очистить заново всеми включёнными слоями» / «Повторить» (если доступна).
2. Сводка: значки по типам («Почта — 1»), значок итога проверки утечек (`good` — «известных скрываемых оригиналов не найдено», `bad` — «найдено оригиналов — N»), значок `warn` «открыто по решению пользователя — N» (сколько значений, с которых в этом чате снята замена, стоит открытыми в этом очищенном тексте; без снятых — значка нет) и значок «слои 1–3, 4, 5» — какие слои выполнены для этого текста (`meta.layers`; текст без отметки очищен до слоёв 4 и 5 — «слои 1–3»). Проверка утечек знает только найденные слоями, скрытые вручную и словарь «всегда скрывать», а снятые замены и список «никогда не скрывать» пропускает намеренно (основная спецификация, раздел 8), поэтому прежнее «оригиналов в очищенном тексте нет» обещало больше, чем она проверяет: после «Снять замену во всём чате» адрес стоял открытым под зелёным значком (аудит 21.10.2026). Что проверка знает, сказано в `title` значка. Ниже сообщениями `warn` / `bad` — предупреждения, заметки, «прежний вариант содержал открытым», блокировка по политике. Для текста в очереди или с ошибкой — только эта часть.
3. Две панели на всю ширину поровну: «Оригинал» (`#original`) и «Очищенный» (`#sanitized`, в заголовке «Скопировать», «Скачать .txt» у выдаваемого). Высота — по содержимому, не больше 60 % высоты окна, дальше прокрутка внутри.
4. Строка «Скрыть фрагмент»: поле значения (`#mask-value`, сюда приходит выделение), тип, основная кнопка «Скрывать во всём чате».
5. Вкладки: «Замены в этом тексте (N)» — таблица с кнопкой `danger` «Снять замену во всём чате»; «Остаточный риск» — пояснение, состояние, догадки, кнопка проверки; состояние идущей или неудачной проверки — и значком на ярлыке вкладки («идёт проверка», `bad` «ошибка проверки», `bad` «проверка прервана»), чтобы его было видно при другой выбранной вкладке; «В словарь» — только администратору; «Эталон» — кнопка и пояснение. Вкладка по умолчанию — «Замены»; выбранная запоминается для этой страницы.

### Таблица замен (`entities.html`)

«Хлебные крошки» «{чат} / Таблица замен», справа кнопка «Очистить тексты чата заново с текущими настройками». Таблица в панели: замена (моноширинным), тип, оригинал (формы написания — серым под ним), вхождений, действия. В действиях видна кнопка `danger` «Снять замену»; «Сменить тип», «Подставлять при восстановлении», «Присоединить» — в `details.inline` «Изменить…», формы раскрываются под строкой.

### Отправка (`send.html`)

## 6. Поведение

**`theme.js`** (подключён без `defer`): ставит на `<html>` класс `js`; читает `localStorage["cleaner-theme"]` (`light` | `dark`) в `try/catch` и, если значение есть, ставит `data-theme`. Ничего больше.

**`app.js`** — дополнения к нынешнему:
- Кнопка темы (`[data-theme-toggle]`, в шапке и на входе): по кругу «как в системе → светлая → тёмная» (дополнение 21.10.2026: прежняя кнопка ставила противоположную действующей, и вернуть следование системе было нельзя). Светлая и тёмная — `data-theme` и запись в `localStorage`; «как в системе» снимает `data-theme` и удаляет ключ, тогда действует `prefers-color-scheme`. Всё — в `try/catch`: без хранилища выбор живёт до перезагрузки.
- Вкладки: контейнер `[data-tabs]`, кнопки `[data-tab="имя"]`, панели `[data-tab-panel="имя"]`. Нажатие показывает свою панель, прячет остальные, ставит `aria-selected`. У контейнера с `data-tabs-remember` (проверка и редактор чата) выбор пишется в `sessionStorage` по ключу `tab:{pathname}` и восстанавливается при загрузке. Панели прячутся только под `html.js`: без JS видны все подряд.
- Копирование (`[data-copy]`, дополнение 21.10.2026): успех — подпись «Скопировано» на 2 с; отказ буфера (запрет браузера, или `navigator.clipboard` нет — адрес не https и не петля) — текст источника выделяется (`Range`), подпись «Не удалось скопировать — текст выделен, нажмите Ctrl+C» на 8 с. Затем подпись прежняя; повторное нажатие перезапускает срок. Итог — и в скрытой области `role="status"` (создаётся при загрузке: созданную в момент объявления читалка пропускает), и в `data-state` кнопки для цвета.
- Перезагрузка по опросу и по концу потока (дополнение 21.10.2026): если на странице начат ввод — у поля значение не исходное (`defaultValue`), выбран файл, у галочки или списка не исходный выбор (у списка без `selected` исходный — первый вариант); скрытые поля не в счёт, — страница не перезагружается. Между шапкой и страницей появляется строка `warn` с `role="status"`: «Готово: {что}. Страница не обновлена, чтобы не сбросить ваш ввод.» и кнопка «Обновить результат» — она перезагружает так же, как без ввода, с сохранением места. «Что» — заголовок элемента ленты («Текст 3», «Ответ локальной модели 5»), на проверке — «обработка текста» или «проверка остаточного риска»; несколько готовых перечисляются через запятую. Опрос после этого не повторяется. Ввод не сохраняется никуда: он просто остаётся в полях, пока страницу не перезагрузят.
- Прокрутка: элемент `[data-scroll-end]` (лента) при загрузке прокручивается к концу, а если в адресе `#item-…` — к этому элементу (браузер переходит к якорю при открытии страницы, но не при перезагрузке). Ленту прокручивает она сама, а не страница, и при перезагрузке по опросу или по концу потока браузер её место не восстанавливает: если читали не конец, перед перезагрузкой верхний видимый элемент ленты и сдвиг от его верха пишутся в `history.state` этой записи истории, при загрузке лента возвращается к ним (элемент, а не число точек: выросший выше элемент не сдвигает место чтения), и запись стирается. Страницу проверки прокручивает `main`, и её место браузер тоже не восстанавливает: по концу проверки риска вкладка с итогом уходила под край окна. Поэтому так же, один раз, сохраняется и возвращается `scrollTop` у `main` — числом точек: перезагрузка меняет только итог во вкладке, всё выше остаётся прежним; возвращается после вкладок, выбранная задаёт высоту страницы. Панели «Оригинал» и «Очищенный» (`pre.text` с `id`) прокручиваются сами — их `scrollTop` сохраняется и возвращается так же. Якорь `#item-…` в адресе сохранённое место не перебивает: Edge при перезагрузке к якорю не переходит (проверено 15.10.2026 — место держится и через 4 с после загрузки, якорь выше и ниже места чтения).

Хранилища браузера держат только имя темы и имя вкладки — никаких данных чатов. `history.state` хранилищем не считается: он живёт в этой вкладке, на этой записи истории, и держит только id элемента, сдвиг и `scrollTop` у `main` и панелей текста.

## 7. Проверка

4. Две копии тёмного набора в `app.css` (по системе и по кнопке темы) совпадают; опрос проверки риска есть в разметке и тогда, когда её вкладка не выбрана.
