# API текстовых запросов Studio

Дополнение к `/api/v1`, реализовано в `cleaner/integration.py` и `cleaner/web/routes_api.py`.
Аутентификация — действующий личный ключ Cleaner в `X-Cleaner-Key` или `Authorization: Bearer`.
Все операции проверяют владельца контекста; ошибки не повторяют входные значения.

## Настройка для пользователей Studio

Администратор Cleaner добавляет включённое облачное подключение и разрешённые модели в
«Настройки → Подключения». Каждый пользователь в своей учётной записи Cleaner создаёт
личный ключ в разделе «Ключи», выбирая это подключение и нужные модели.
Несколько ключей одной учётной записи имеют общего владельца контекстов: для разных
пользователей Studio нужны отдельные учётные записи Cleaner.

В Studio параметры находятся в **Настройки → Защита данных**: адрес Cleaner, личный ключ,
проверка связи, список моделей и модель по умолчанию отдельно для чата и перевода.
Один личный ключ можно использовать в обоих разделах. Облачный ключ остаётся в Cleaner;
пустое поле личного ключа при правке подключения Studio сохраняет прежнее значение.
Умолчания применяются к новым диалогам и переводам. Проверочный облачный запрос выполняется
через обычный предпросмотр в чате; проверка связи сама по себе не отправляет текст модели.

## Контракт

| Метод и путь | Назначение |
|---|---|
| `GET /api/v1/models` | Модели включённого подключения, разрешённые ключу. Ключ без подключения или ключ подписки — 403. |
| `POST /api/v1/chats` | Обычный API-контекст владельца с собственной зашифрованной таблицей замен. |
| `POST /api/v1/chats/{id}/requests` | Подготовить весь текстовый запрос без обращения к облачной модели. |
| `POST /api/v1/chats/{id}/requests/send` | Проверить и однократно отправить запрос, выданный программе в `requests`. |
| `POST /api/v1/chats/{id}/local-requests` | Показать оригиналы и назначение явного запроса локальной модели. |
| `POST /api/v1/chats/{id}/local-requests/send` | Однократно отправить оригиналы по локальной квитанции. |
| `GET /api/v1/chats/{id}/answers/{item}/events` | SSE с восстановленным текстом и конечным состоянием. |
| `POST /api/v1/chats/{id}/answers/{item}/stop` | Остановить облачный или локальный ответ; после завершения — 204 без изменений. |
| `DELETE /api/v1/chats/{id}` | Удалить контекст штатной ChatService, включая активные задания, ключ таблицы и примеры эталона из этого чата. |

Тело `requests`: `model`, непустой список `messages` с `role: system|user|assistant` и строковым
`content`; последнее сообщение — `user`. Изображения, инструменты и файловые блоки не принимаются.
Суммарная длина ограничена обычным `max_text_chars`. Действует общий допуск очереди и памяти.
Необязательный `rules` — до ста `{action: mask|unmask, value, type}`. Правило действует только
в контексте; фрагмент должен присутствовать в запросе. Маска не может ослаблять строгую политику.

Ответ: `deliverable`, фактические очищенные `messages`, `counts`, позиции `replacements`, числа
`blocked` и `leaks`, `digest`, непрозрачная `receipt`. При блокировке `messages` пустой: выдавать
запрещённый результат нельзя. Адреса и ключи провайдера клиенту не возвращаются.

Тело `requests/send`: только `receipt`. Модель, тексты и адрес не могут быть заменены при отправке.
Ответ 202 — `item_id`. Квитанция зашифрована ключом контекста, связана с id ключа, версией контекста,
параметрами подключения и слоями; живёт десять минут. Отправка атомарно меняет версию контекста:
повтор, новый предпросмотр, правка, удаление или истечение срока делают старую квитанцию недействительной.
Перед отправкой запрос пересобирается с текущими политиками, сравнивается отпечаток и повторяется
проверка утечек в обычном egress. Находки моделей для неизменного текста берутся из квитанции.

Что гарантирует квитанция: уйдёт ровно тот запрос, который Cleaner вернул программе в `requests`, с теми же
моделью, подключением и слоями, и только один раз. Что она не гарантирует: что этот запрос видел человек.
Подтверждение — вызов программы с действующим ключом: скрипт с тем же ключом может вызвать `requests` и сразу
`requests/send`. Показ запроса пользователю и его подтверждение — обязанность программы (в Studio — предпросмотр
в чате); для Cleaner это отступление от FR-8.4 (ТЗ, FR-13.7 и таблица отступлений раздела 6.13).

В SSE событие `text` несёт весь текущий восстановленный префикс, а не дельту: клиент **заменяет**
показанный текст. Он может уточняться после завершения ссылки. `done` содержит `status`, окончательный
`text`, исходный `raw`, `counters` и `error`. Отсутствие `done` — оборванный ответ. Применяется обычный
браузерный StreamRestorer с защитой внешних ссылок, а не восстановление аргументов инструментов агента.
Закрытие читателя не отменяет генерацию; отмена — отдельной командой.

### Явный локальный запрос

После облачной блокировки Studio позволяет выбрать «Локальная модель», заново показать запрос и
подтвердить отправку оригиналов. `local-requests` принимает только `messages` с теми же ограничениями;
облачное подключение и его ключ не нужны. Личный ключ Cleaner и проверка владельца обязательны.
Ответ содержит `route: local`, `originals: true`, исходные `messages` и `destination: {url, model}`.
Настроенный адрес допускается только по SEC-12: петля, частный IP или явно доверенный узел.
`destination.url` видит владелец любого ключа, поэтому логин и пароль в адресе не допускаются ни формой
настроек, ни при каждом использовании. Ключ локального шлюза остаётся на сервере.

Локальная квитанция связана с ключом, контекстом, сроком, моделью, адресом и настройками локального
клиента; перед отправкой они проверяются повторно. Её нельзя использовать на облачном маршруте.
Ответ идёт через ту же очередь, лимиты, SSE и остановку; его оригинальный текст не проходит обратную
подстановку облачных меток. При отказе автоматического переключения маршрута нет.
Для обоих маршрутов пределы распакованного ответа — 32 МиБ и 2 МиБ на строку SSE до JSON-разбора;
сохраняемый текст не превышает `max_text_chars`, разрешённый префикс сохраняется как `partial`.

Историю ведёт Studio и передаёт целиком. До отправки Cleaner хранит только таблицу замен;
исходная история находится внутри зашифрованной краткоживущей квитанции у клиента. После отправки
сырой ответ сохраняется обычным зашифрованным элементом чата Cleaner. События аудита содержат
только идентификаторы и счётчики. Глобальные словари и политики администратора сохраняют прежнюю
область действия; правила `requests.rules` контекстные и не меняют другие чаты.
