# API текстовых запросов Studio

Дополнение к `/api/v1`, реализовано в `cleaner/integration.py` и `cleaner/web/routes_api.py`.
Аутентификация — действующий личный ключ Cleaner в `X-Cleaner-Key` или `Authorization: Bearer`.
Все операции проверяют владельца контекста; ошибки не повторяют входные значения.

## Контракт

| Метод и путь | Назначение |
|---|---|
| `GET /api/v1/models` | Модели включённого подключения, разрешённые ключу. Ключ без подключения или ключ подписки — 403. |
| `POST /api/v1/chats` | Обычный API-контекст владельца с собственной зашифрованной таблицей замен. |
| `POST /api/v1/chats/{id}/requests` | Подготовить весь текстовый запрос без обращения к облачной модели. |
| `POST /api/v1/chats/{id}/requests/send` | Проверить и однократно отправить показанный запрос. |
| `GET /api/v1/chats/{id}/answers/{item}/events` | SSE с восстановленным текстом и конечным состоянием. |
| `POST /api/v1/chats/{id}/answers/{item}/stop` | Остановить облачный ответ. |
| `DELETE /api/v1/chats/{id}` | Удалить контекст штатной ChatService, включая активные задания и ключ таблицы. |

Тело `requests`: `model`, непустой список `messages` с `role: system|user|assistant` и строковым
`content`; последнее сообщение — `user`. Изображения, инструменты и файловые блоки не принимаются.
Суммарная длина ограничена обычным `max_text_chars`. Действует общий допуск очереди и памяти.
Необязательный `rules` — до ста `{action: mask|unmask, value, type}`. Правило действует только
в контексте; фрагмент должен присутствовать в запросе. Маска не может ослаблять строгую политику.

Ответ: `deliverable`, фактические очищенные `messages`, `counts`, позиции `replacements`, числа
`blocked` и `leaks`, `digest`, непрозрачная `receipt`. При блокировке `messages` пустой: выдавать
запрещённый результат нельзя. Адреса и ключи провайдера клиенту не возвращаются.

Тело `requests/send`: только `receipt`. Модель, тексты и адрес не могут быть заменены при отправке.
Ответ 202 — `item_id`. Квитанция зашифрована ключом контекста, связана с id ключа, версией контекста,
параметрами подключения и слоями; живёт десять минут. Отправка атомарно меняет версию контекста:
повтор, новый предпросмотр, правка, удаление или истечение срока делают старую квитанцию недействительной.
Перед отправкой запрос пересобирается с текущими политиками, сравнивается отпечаток и повторяется
проверка утечек в обычном egress. Находки моделей для неизменного текста берутся из квитанции.

В SSE событие `text` несёт весь текущий восстановленный префикс, а не дельту: клиент **заменяет**
показанный текст. Он может уточняться после завершения ссылки. `done` содержит `status`, окончательный
`text`, исходный `raw`, `counters` и `error`. Отсутствие `done` — оборванный ответ. Применяется обычный
браузерный StreamRestorer с защитой внешних ссылок, а не восстановление аргументов инструментов агента.
Закрытие читателя не отменяет генерацию; отмена — отдельной командой.

Историю ведёт Studio и передаёт целиком. До отправки Cleaner хранит только таблицу замен;
исходная история находится внутри зашифрованной краткоживущей квитанции у клиента. После отправки
сырой ответ сохраняется обычным зашифрованным элементом чата Cleaner. События аудита содержат
только идентификаторы и счётчики. Глобальные словари и политики администратора сохраняют прежнюю
область действия; правила `requests.rules` контекстные и не меняют другие чаты.

## Проверки

    .venv/Scripts/python.exe -m pytest -n0 tests/test_integration_api.py tests/test_web_api.py

Сквозная проверка — в соседнем Studio: `tests/test_cleaner_contract.py` и `tests/test_ui_cleaner.py`.
Для неё `tests/studio_server.py` поднимает Cleaner только на 127.0.0.1 с временной базой, вымышленными
данными и заглушкой провайдера; TLS проверяется отдельным самоподписанным сертификатом теста.
