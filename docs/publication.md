# Публичная публикация

GitHub начинается с очищенного снимка. Прежняя история сохранена только в приватном источнике,
включая тег `pre-public-2026-11-04`; её коммиты и теги нельзя отправлять в публичный репозиторий.
Файлы рабочего дерева очищены, но это не очищает родительские коммиты приватной ветки.

Публичный состав исключает реальные профили `deploy/hosts/`, `.claude/`, локальные данные,
эксплуатационные инструкции, рабочие планы, отчёты и внутренние журналы.
Приватный источник может сохранять эти файлы для синхронизации рабочих машин;
правила `export-ignore` в `.gitattributes` исключают их из `git archive`.
В Git остаются безопасный `example.conf`, код, тесты, требования и спецификации с вымышленными адресами.
Примеры ключей в тестах вымышлены и помечены `secret-scan:allow` на соответствующих строках.
GitHub проверяет ключи независимо от этой пометки. Полные форматы, похожие на настоящие ключи,
собираются из частей: значения тестовых входов сохраняются, готовых ключей в исходниках нет.

## Обновление из приватной рабочей копии

1. Проверьте diff и выполните тесты из `CLAUDE.md`, затем закоммитьте изменения в приватном источнике.
2. Возьмите только файлы `git archive HEAD`, убедившись, что сработал `export-ignore`.
   Не клонируйте историю приватной ветки в GitHub.
3. Обновите ими отдельную рабочую копию публичной `main`, удаляя файлы, которых больше нет в снимке.
   На первой публикации создайте независимый корневой коммит; на последующих сохраняйте публичного родителя.
4. Проверьте набор файлов, ссылки Markdown, синтаксис и запустите быстрые тесты именно публичной копии.
5. Запустите проверки приватности всего исходящего диапазона: имена файлов, форматы ключей,
   персональный denylist и значения секретов. При `BLOCKED` исправьте причину до публикации.
6. Отправьте только публичную `main` обычным push без `--force`, затем проверьте SHA и анонимное чтение.

На рабочей машине отдельная публичная копия хранится в игнорируемом `data/github-public/`.
Владелец использует общий `github-push.sh`; локальные `.sanitize-patterns` и `.github-push-deny`
копируются в публичную рабочую копию перед проверкой и не включаются в коммит.
Публичный remote исходной приватной копии имеет заблокированный `pushurl`, чтобы случайный push
старой истории завершался ошибкой. Для публикации используется remote отдельной публичной копии.
