# Публичная публикация

Основная ветка содержит полную очищенную историю разработки. После проверок
одни и те же коммиты отправляются в основной репозиторий и GitHub; pull-зеркало
получает их с основного сервера. Отдельная история публичных снимков не используется.
Резервные Git-bundle прежней приватной истории остаются только локально и не
публикуются в ветках или тегах.

Публичный состав исключает реальные профили `deploy/hosts/`, `.claude/`, локальные данные,
эксплуатационные инструкции, рабочие планы, отчёты и внутренние журналы.
Эти файлы сохраняются локально вне Git; правила `export-ignore` в `.gitattributes`
дополнительно исключают их из `git archive`. Сообщения и метаданные коммитов тоже очищены.
В Git остаются безопасный `example.conf`, код, тесты, требования и спецификации с вымышленными адресами.
Примеры ключей в тестах вымышлены и помечены `secret-scan:allow` на соответствующих строках.
GitHub проверяет ключи независимо от этой пометки. Полные форматы, похожие на настоящие ключи,
собираются из частей: значения тестовых входов сохраняются, готовых ключей в исходниках нет.

## Последующие изменения

1. Проверьте diff и выполните проверки из `CLAUDE.md`.
2. Закоммитьте изменения в основной рабочей копии.
3. Проверьте весь исходящий диапазон: имена файлов, форматы ключей,
   персональный denylist и значения секретов. При `BLOCKED` устраните причину.
4. Отправьте текущую основную ветку в основной репозиторий и GitHub.
5. Запустите синхронизацию pull-зеркала и сравните SHA ветки и последнего коммита.

Проверки и публикация в GitHub выполняются штатным `github-push.sh`.
Локальные `.sanitize-patterns` и `.github-push-deny` не входят в коммиты.
Для обычных последующих публикаций переписывание истории не требуется.

## Установка

Реальные профили `deploy/hosts/<имя>.conf` и прежние рабочие инструкции в
`docs/private/` хранятся локально вне Git. При доставке `git archive` профиль
добавляется отдельно в защищённый каталог установки. Установщик сохраняет
его в `/etc/cleaner/host.env`. Настройки, ключи, сертификаты и SQLite сохраняются
по прежним путям; публикация истории не требует перезапуска службы.
