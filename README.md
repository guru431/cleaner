# Cleaner

Локальная псевдонимизация перед облачной LLM: убирает из текста и документов персональные и
учётные данные и сведения об инфраструктуре, хранит зашифрованную таблицу соответствий и
восстанавливает оригиналы в ответе модели.

Очистка идёт пятью слоями: правила, секреты, инфраструктура и словари, локальные модели
распознавания имён (CPU, без сети), локальная LLM. Перед отправкой можно проверить и поправить замены.
Есть веб-интерфейс, API для приложений и шлюз агентов с протоколами Anthropic, Chat Completions и Responses.

## Из чего состоит

- `cleaner/` — конвейер очистки и восстановления, обработка документов, шифрованное хранилище,
  отправка в облако, веб-интерфейс и замеры качества.
- `deploy/` — установщик Linux, юниты systemd, ограничения сети, проверка сервера и замки зависимостей.
- `scripts/` — проверки компонентов и загрузка открытых наборов для замеров.
- `tests/` — тесты и вымышленные примеры запросов агентов.

## Запуск для разработки

Нужен Python 3.12 или новее. Замки зависимостей разделены для Windows и Linux.
Создайте окружение: `python -m venv .venv`. На Windows:

```powershell
.venv/Scripts/python.exe -m pip install --require-hashes -r requirements-dev.txt
.venv/Scripts/python.exe -m cleaner init --admin dev --env-file data/cleaner.env
.venv/Scripts/python.exe -m cleaner models download
```

На Linux используйте `.venv/bin/python` и `requirements-dev-linux.txt`.
Модели слоя 4 и Docling занимают около 2 ГБ. Для запуска передайте переменные из
`data/cleaner.env` окружению процесса и выполните `python -m cleaner serve` интерпретатором окружения.
В Git Bash или Linux после активации окружения:

```bash
set -a; . data/cleaner.env; set +a
python -m cleaner serve
```

По умолчанию интерфейс доступен на `http://127.0.0.1:5464`, данные лежат в `data/`.
Главный ключ, база и модели не попадают в Git. Для слоя 5 и OCR настройте локальный шлюз
и передайте `CLEANER_GATEWAY_KEY` окружением. Облачные подключения добавляются в интерфейсе.
Для доступа с других компьютеров настройте TLS и явный список клиентских сетей.

## Тесты

```powershell
.venv/Scripts/python.exe -m pytest                       # быстрый набор, бюджет 60 с
.venv/Scripts/python.exe -m pytest tests/<файл>.py       # точечно
.venv/Scripts/python.exe -m pytest -n 0 -m "not manual"  # полный набор
```

Дополнительные проверки после изменения слоёв очистки или шлюза — в разделе Tests [CLAUDE.md](CLAUDE.md).
Сетевые проверки, модели и тяжёлые замеры включаются явно маркером `integration`.

## Установка и интеграции

Установка Linux описана в [docs/deployment.md](docs/deployment.md). Публичный профиль
`deploy/hosts/example.conf` слушает только петлевой адрес; рабочий профиль с адресами и сетями
создаётся локально и передаётся на сервер отдельно от Git.

[API для Studio](docs/studio-api.md) даёт предпросмотр, контекстные правки, одноразовую
зашифрованную квитанцию отправки и потоковое восстановление ответа. Облачный ключ остаётся в Cleaner;
приложение использует личный ключ с доступом к подключению и моделям.
